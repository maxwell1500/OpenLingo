# `duo-android/tools/` — development-only tooling

Nothing in this directory ships. It is outside `app/`, so it is not part of any
Android `sourceSet` and cannot be packaged into the APK (see
`app/build.gradle.kts`: no `sourceSets`, `resources` or `packaging` block is
configured, and the only packaged inputs are `app/src/main/{assets,java,res}`).

## `g2p_fixes.py`

The shared G2P patch module. It patches three upstream Kokoro-82M / misaki
defects at synthesis time — two Japanese, one Spanish — and documents a fourth
class as a deliberate *non*-fix:

- `わ` / `ゎ` / `うぃ` / `うぇ` / `うぉ` render as voiceless labiodental `ɸ`, not
  `β` (upstream's HEPBURN table maps them to `β`, the Spanish voiced bilabial
  fricative, while using the correct `ɸ` for `ふ`).
- Geminate consonants upstream's commented-out set omits — every affricate and
  sibilant — so `っち` / `っし` geminate instead of producing `ʔ`.
- Spanish: espeak-ng emits both `/x/` and a spurious `/j/` for a single written
  `g` before `o` (`cogió` → `koxjo`); the doubled-palatal signature is
  repaired, plain `/x/` in `jefe`, `viajar`, `dijimos` … is left alone.
- **Not** patched: Kokoro's English G2P writes the `/au/` and `/ei/` diphthongs
  as capital ASCII `W` and `A`. Those are legitimate Kokoro phonemes, so
  `aunque` and `peina` are correct as-is. Do not reintroduce this class
  without re-running the check.

`READING_OVERRIDES` pins the tagger readings upstream gets wrong — `日本語`,
`川`, `停留所`, `一枚`, `一冊`, plus `私` / `明日` / `来させる` where the app's
own declared romaji field disagrees with fugashi — without disturbing the ones
it already gets right (`一緒`, `一人`, `一つ`, `一切`).

Read the module's own header comments before changing it — they explain why
each override exists and, just as importantly, which readings are deliberately
*not* pinned.

### Using it

Always build the pipeline through `make_pipeline()`; a bare `KPipeline` carries
all four defects, because the bugs live in the kana→IPA step that sits
downstream of the tagger.

```python
import g2p_fixes

pipeline = g2p_fixes.make_pipeline(lang_code="j")   # or "e" for Spanish
ipa = g2p_fixes.jpn_g2p("買った")                     # k a t t a, never kaʔta
```

Use it for **both** synthesis and verification. Verifying through
`pyopenjtalk.g2p()` measures a different stage of the pipeline than the audio
goes through — that gap is exactly how `がっこう` / `きって` / `はっぴょう`
shipped with a glottal stop while the checks looked clean.

`READING_OVERRIDES` is a module global and the patched closure reads it on every
call, so an audit can toggle it at runtime by rebinding
`g2p_fixes.READING_OVERRIDES` rather than by editing this file.

### Self-test

```
python g2p_fixes.py
```

Prints the `わ` / `っ` / Spanish-palatal cases with an explicit
`beta=` / `glottal=` / `xj=` flag per line. It needs no audio output and no
network beyond the Kokoro weights.

### Reproducing the shipped audio

The clips under `app/src/main/assets/audio/` were generated by the generator
scripts in the working tree's `.scratch/` directory, all of which route through
`g2p_fixes.make_pipeline()`. Those generator scripts themselves are not committed;
this module is, because without it a clean clone cannot reproduce the audio.
